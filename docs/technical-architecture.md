## 2. 数据安全架构

### 2.1 多重加密保护

#### 密钥派生机制
- 主密码通过PBKDF2-SHA256算法派生（100,000次迭代）
- 与钱包私钥签名结合生成主加密密钥
- 每个数据条目使用唯一的IV（初始化向量）
- 采用AES-256-GCM进行认证加密

#### 密钥验证流程
1. 用户输入主密码
2. 通过PBKDF2派生密钥材料
3. 结合钱包签名生成验证密钥
4. 尝试解密验证字符串
5. 验证HMAC确保数据完整性

### 2.2 零知识存储架构

#### 数据加密流程
1. 客户端生成随机数据加密密钥
2. 使用用户主密钥加密数据加密密钥
3. 使用数据加密密钥加密实际数据
4. 所有加密操作在客户端完成

#### 数据存储结构
```json
{
    "metadata": {
        "version": "1.0",
        "created": "timestamp",
        "updated": "timestamp"
    },
    "keyBundle": {
        "encryptedKey": "base64",
        "iv": "base64",
        "algorithm": "AES-GCM"
    },
    "data": {
        "ciphertext": "base64",
        "iv": "base64",
        "tag": "base64"
    }
}
```

### 2.3 去中心化存储机制

#### IPFS存储流程
1. 数据本地加密
2. 计算加密数据的CID
3. 将CID与用户钱包地址绑定
4. 数据分片存储到IPFS网络
5. 通过智能合约记录数据映射

#### 数据同步机制
1. 设备间通过CID索引同步
2. 使用DHT网络发现数据位置
3. 并行获取数据分片
4. 本地解密和验证数据

### 2.4 安全防护措施

#### 防暴力破解
- 密码尝试次数限制
- 指数级增长的延迟
- IP地址监控
- 异常行为检测

#### 会话安全
- 基于JWT的会话管理
- 定期轮换会话密钥
- 多设备会话控制
- 自动会话超时

#### 数据完整性
- 所有数据包含HMAC签名
- 版本历史记录
- 改动审计日志
- 定期完整性检查
